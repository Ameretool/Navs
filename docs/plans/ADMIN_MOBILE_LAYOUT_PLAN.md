# 后台管理移动端布局优化开发计划

## 1. 目标与范围

本次只调整后台管理页面的响应式布局和展示密度，不改变 API、数据结构、权限逻辑、导入导出语义或桌面端已有业务流程。

目标：

- 顶部标题、返回首页、退出登录和后台菜单正常错行显示，任何视口下不互相遮挡。
- 移动端分类管理、访问分析的统计指标在同一行展示。
- 移动端书签列表在页面宽度内完成展示，不依赖左右滚动；保留编辑、删除等操作入口。
- 移动端零访问书签的标题和地址按指定字符数截断，同时保留完整链接和可访问名称。
- 删除站点设置标题下的辅助描述，减少设置页面首屏高度。
- 移动端导入来源、导入模式和“选择文件并导入”控件形成稳定、可读的对齐关系。

本轮已明确不直接修改业务代码；本文档作为后续实现和验收依据。

## 2. 当前问题与证据

源码审计确认以下现状：

- `AdminPageHeader.svelte` 将操作按钮放在 `header` 外，并使用 `position: fixed`。当前提交将其 `z-index` 提高到 `1000`，只能改变覆盖顺序，不能解决标题和菜单的空间竞争，且会遮挡导航内容。
- `AdminSidebar.svelte` 在 `700px` 以下固定在底部，高度为 `60px`；`Admin.svelte` 通过底部 padding 为内容预留空间，但顶部操作区没有占用正常文档流高度。
- `adminListPanels.css` 在 `960px` 以下把 `.admin-status-panel` 改为单列，因此分类和访问分析的统计项在移动端逐项占据整行。
- `BookmarkListPanel.svelte` 使用桌面表格列和 `min-width: 760px`；移动端 CSS 目前隐藏了 URL 和打开方式列，但没有把移动端需要的信息重新组织到标题区域，且标题、复选框、操作列缺少紧凑布局契约。
- `AnalyticsPanel.svelte` 的零访问列表已有 CSS 省略号，但没有按字符数稳定截断，窄屏下仍可能被长文本撑开或难以扫描。
- `SettingsPanel.svelte` 的 `.panel-desc` 文案正是需要删除的“按功能区管理站点信息……”描述。
- `BackupPanel.svelte` 的 `.import-actions` 使用可换行 flex，移动端两个 `min-width: 180px` 的字段和按钮会自然换行，导致导入模式与按钮不在同一水平关系中。

本轮尝试连接本地配置指向的真实项目地址并使用 `390x844` 移动视口截图。浏览器扩展不可用，Chrome DevTools 会话在截图等待阶段超时，未生成可交付截图；因此本计划以用户反馈和当前源码为主要依据，后续实现必须补做真实浏览器截图验收。

## 3. 设计边界与状态所有权

| 责任 | 模块 | 允许修改的内容 |
| --- | --- | --- |
| 后台页头编排 | `src/components/admin/AdminPageHeader.svelte` | 标题、顶部按钮的 DOM 顺序、网格/错行布局和响应式间距 |
| 移动端主菜单 | `src/components/AdminSidebar.svelte` | 仅保留底部菜单的固定定位和安全区预留；不通过层级覆盖页头 |
| 列表共享布局 | `src/components/admin/adminListPanels.css` | 统计面板、表格外层、移动端公共间距和列宽 |
| 书签展示 | `src/components/admin/BookmarkListPanel.svelte` | 移动端书签行的信息组合、显示字段和操作列 |
| 访问分析展示 | `src/components/admin/AnalyticsPanel.svelte` | 零访问列表的显示截断和紧凑布局 |
| 设置展示 | `src/components/SettingsPanel.svelte` | 删除面板描述，不改变设置表单状态和提交流程 |
| 备份导入展示 | `src/components/BackupPanel.svelte` | 导入控件的响应式排列；文件选择和导入回调保持不变 |
| 纯文本规则 | 新增小型纯函数模块（如确有复用需要） | 按 Unicode 字符数截断，并由单元测试覆盖 |

不新增全局可变状态，不改变组件之间的事件接口，不把布局判断放入 `App.svelte` 或 API 层。

## 4. 实施步骤

### 4.1 重做后台页头的错行布局

1. 将 `.admin-header-actions` 放入 `.page-header` 内部，与标题区域成为同一个布局容器。
2. 桌面端使用 `grid-template-columns: minmax(0, 1fr) auto`，标题区域允许收缩，按钮区域保持自身宽度。
3. 移动端改为正常文档流的两行结构：第一行显示“管理后台/导航内容管理”，第二行靠右显示返回首页和退出登录按钮；必要时让按钮区域占满一行并使用 `justify-content: flex-end`。
4. 删除页头操作区的 `position: fixed` 和依赖 `z-index` 解决遮挡的方案，改用 `min-height`、`gap`、`padding` 让页头高度由两行内容自然撑开。
5. 保留 `data-testid`、`aria-label`、按钮回调和登录态分支。移动端底部菜单继续位于页面底部，不能覆盖页头或内容。

验收重点：标题、按钮、菜单三者的 `DOMRect` 不相交；页面内容起点大于页头底部；返回首页和退出按钮均能通过真实点击命中。

### 4.2 统计指标移动端并排

1. 在共享 `.admin-status-panel` 的移动端断点覆盖当前 `grid-template-columns: 1fr`，改为三列等宽网格。
2. 缩小移动端 padding、列间距和 `.admin-status-item` 内部 gap；标签和数值允许在自己的单元格内省略或换行，但三个指标不能改成纵向堆叠。
3. 同一规则同时覆盖分类管理和访问分析，桌面端继续保持现有三列布局。

验收重点：`390x844` 和窄屏设备下三个指标处于同一行，统计卡片高度不会异常增长，文字不溢出相邻单元格。

### 4.3 移动端书签列表改为紧凑信息行

1. 桌面端表格列保持现状；移动端将表格设置为 `width: 100%`、`min-width: 0`、固定布局，去掉 `760px` 的移动端最小宽度约束。
2. 移动端只保留必要的复选框、标题信息区和操作区，重新设置列宽：复选框列缩小，标题列占主要空间，操作列保留编辑/删除按钮的最小可用宽度。
3. 移动端隐藏独立的分类列和打开方式列；将分类和打开方式作为标题下方的紧凑 metadata 显示，避免继续占用表格列。
4. 将 URL 作为标题信息区的可点击次级内容显示或保留为受控窄列，必须设置 `min-width: 0` 和省略规则，不能把操作列推到屏幕外。
5. 移动端隐藏原有备注/描述段落，保留完整内容在 DOM 的 `title` 或可访问名称中，避免用户失去辨识信息。
6. 标题显示最多 12 个字符，超出显示省略号；完整标题保留在 `title`、`aria-label` 或可访问文本中。复选框到标题内容的水平 gap 和单元格 padding 由当前桌面值缩小到移动端专用值。
7. 排序模式、全选、批量删除、编辑、删除和分页不能因移动端列隐藏而失效；排序模式下的拖拽列需要使用相同的紧凑宽度规则。

建议将“按 Unicode 字符数截断并保留完整原文”的逻辑提取为纯函数，避免用 CSS 宽度近似 12 个字符；如果只在两个组件使用，也可以先放在各自组件内并补充等价测试，禁止复制不一致的截断实现。

验收重点：移动端无需横向滚动即可看到标题和所有操作按钮；标题超长时显示不超过 12 个字符；分类、打开方式出现在标题下方；备注不显示；完整标题仍可通过辅助文本获取。

### 4.4 零访问书签截断

1. 在 `AnalyticsPanel.svelte` 中对零访问列表标题设置最多 20 个字符的显示规则。
2. 对 URL 设置最多 20 个字符的显示规则，完整 URL 继续作为 `href`，并通过 `title` 或 `aria-label` 提供完整值。
3. 保持现有分类标签、链接点击行为、分页和空状态不变；使用 `min-width: 0` 防止长文本撑开 flex 项。

验收重点：标题和地址各自最多显示 20 个字符（省略号包含在显示预算内），长 URL 不造成横向滚动。

### 4.5 删除站点设置辅助描述

1. 删除 `SettingsPanel.svelte` 中标题下方的 `.panel-desc` 元素及其仅用于该元素的样式。
2. 保留保存状态提示、保存按钮、设置分区提示和设置表单；不要删除 `.settings-submenu` 中的功能区 hint，除非后续截图验证确认那是同一段文案。
3. 桌面和移动端都验证设置标题、保存按钮、分区菜单与表单之间的间距，避免删除文案后留下空白区域。

### 4.6 调整数据备份与导入控件

1. 桌面端继续使用单行 flex，来源、模式和按钮保持底部对齐。
2. 移动端将 `.import-actions` 改为明确的 grid：导入来源独占第一行；导入模式和“选择文件并导入”按钮位于第二行并排；控件宽度使用 `minmax(0, 1fr)`，不再继承 `180px` 的硬性最小宽度。
3. 按钮设置 `white-space: nowrap` 或合理的窄屏字体/内边距，确保按钮文字不被截断；导入中、未登录和禁用态保持现有行为。
4. 不改变 `importSource`、`importMode`、文件类型判断、拖放行为和 `onImportData` 调用参数。

验收重点：移动端第二行的导入模式选择框和导入按钮处于同一水平线；来源选择独立且完整可见；按钮不会把父容器撑出屏幕。

## 5. 验证计划

### 静态与单元验证

- 为文本截断纯函数增加边界测试：空字符串、恰好长度、超长中文、英文、Emoji/组合字符。
- 为现有后台布局测试补充源码契约检查：页头操作区不再使用固定定位、移动统计为三列、移动书签隐藏列与移动 metadata 存在、设置描述不存在、备份控件有移动 grid 契约。
- 运行 `npm run type-check`、`npm test`、`npm run build` 和 `git diff --check`。

### 真实浏览器验证

使用本地忽略配置中的真实项目地址，复用用户已授权的浏览器连接；只创建一个专用 target，使用真实点击切换后台菜单，不写入设置、不导入文件、不删除数据。

覆盖视口：

- `390x844`：窄屏移动端主验收视口；
- `430x932`：较宽移动端，验证按钮和导入控件没有过度留白；
- `768x1024`：平板/窄桌面断点，验证页头和表格不会提前切换到错误布局；
- 至少一个桌面视口，确认桌面表格、设置双栏和备份单行布局没有回归。

逐页截图和检查：

- 分类管理：页头错行、统计三列、底部菜单、内容不被覆盖；
- 书签管理：无横向滚动、12 字符标题、标题下 metadata、操作按钮可见；
- 访问分析：统计三列、零访问标题/地址 20 字符截断；
- 站点设置：描述删除后头部高度和保存操作正常；
- 数据备份与导入：来源、模式、按钮的移动端对齐关系。

同时记录控制台 error/assert、页面异常、失败请求和非预期 4xx/5xx。测试结束只关闭本次创建的 target，确认没有遗留测试页面、截图或临时目录。

## 6. 实施顺序与完成标准

建议顺序：

1. 重做 `AdminPageHeader` 的正常流错行布局，并删除单纯提高层级的方案。
2. 调整共享统计面板和书签表格移动规则。
3. 实现零访问列表截断与必要的纯函数测试。
4. 删除设置描述并调整备份导入 grid。
5. 运行静态检查和单元测试。
6. 用真实浏览器截图逐页复核，修正尺寸后再提交。

完成必须同时满足：

- 所有用户列出的页面问题在移动视口下可复现验证并已修复；
- 页头标题和操作按钮不再依赖覆盖层级，导航菜单内容不被遮挡；
- 移动端书签列表不需要左右滚动即可完成查看和操作；
- 完整标题、URL 和按钮语义没有因视觉截断丢失；
- 桌面端既有表格、设置、备份操作和权限行为没有回归；
- 相关检查和真实浏览器验证通过后，才进入实现提交阶段。
